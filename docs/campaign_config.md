# 城池和国家开局配置

编辑 `assets/data/campaign_config.json`，保存后热重启 Flutter。JSON 在资源加载时读取一次；普通“重新开始”使用本次已加载的配置重新创建战役。无需修改 ROM 或包含地形图块的 `assets/maps/worlds.json`。

国家与城池文件包含 16 个国家和三张地图的全部 33 座城，英雄配置集中在 `rom_heroes.json`。`id` 用于关联，`name` 是便于查找的标签；正式名称和国旗仍来自地图目录。地图编号 0、1、2 对应地图一、二、三。

## 每座城市

例如，地图一的奥尔梅：

```json
{
  "id": 1,
  "name": "奥尔梅",
  "baseIncome": 20,
  "initialReserveSoldiers": 10,
  "initialLevel": 2
}
```

| 字段 | 含义 |
|---|---|
| `baseIncome` | 一级城的基础月产出；每高一级额外 +5，再按收成和月俸结算 |
| `initialReserveSoldiers` | 开局城内全部兵员，驻城将领不另带免费兵；出征或迎战时再从中领取 |
| `initialLevel` | 初始城防等级，1–5，影响外观、月产出、储备容量和守城攻击加成 |

目前阿尔马基础产出为 10，奥尔梅为 20，其余城池先设为 10。二级奥尔梅的实际月产出因此是 25，城池易主降至一级后为 20。每座城的初始储备均填为 10；想设空兵营可改为 0。初始等级先沿用之前的地图等级，每张地图可以分别修改。

储备上限为 **城防等级 × 4 + 本城所属存活英雄数 × 4**。二级城、三名英雄提供 8 + 12 = 20 个名额；各城分别计算，国家总容量是所有城池之和。出征、扎营的英雄仍计入出发城，进驻另一城后名额转移，招募签约后新增名额，阵亡后移除名额；待签约结果不计入。初始化先按 ROM 记录去重英雄归属，再验证初始储备不超过实际容量。将领仍最多带四兵，扩容不会免费生成新兵。

## 将领月俸与解雇

`assets/data/rom_heroes.json` 的 `heroes` 数组同时定义英雄顺序、属性与月俸：

```json
{"id": 0, "name": "泽拉斯", "salary": 3}
```

直接修改 `salary` 金币数即可。`id` 是英雄身份编号，`name` 用于查找；数组当前按展示顺序排列，调换数组位置会改变展示与迎战顺序，金额仍跟随对应英雄。主角 `id: 40` 固定为零且不占分档名额，从泽拉斯开始，第 1～5 位每月 3 金币，第 6～10 位 2 金币，第 11～15 位 1 金币，第 16 位起免费。这是新游戏平衡，原版报酬保存在同一条记录的 `romSalary` 中，仅用于对照。

开局驻军、招募预览、签约后月俸及全国月结都读取同一份配置。修改后热重启加载新开局；每位英雄必须填写 `salary`，负数、非整数、重复或不存在的编号会报错，主角不接受非零月俸。

我方城内与野外英雄面板下方的“取消”替换为红色“解雇”，同时显示返还金币；右上角关闭入口和取消选点仍可使用。高级将领返还 `10 + 内政` 金币，普通将领返还 `5 + 内政` 金币，返还进入所属国家国库。点击后立即离队并回到全国家共享招募池，停止后续月俸和野外粮草；重复点击或持有过期身份不能重复返款，重新签约后使用本局 JSON 月俸。

主角不可解雇，交战及结束动作期间暂不可解雇，敌国将领只有查看入口。城内解雇保留库存，英雄减少导致容量降低时仍按既有规则裁掉超额兵员；野外解雇的随军士兵一起离队，不远程归还。解雇不改变城防、归属和当月已签约次数，哪怕最后一位守将被解雇，城池也只会变为空城。返还基础金额由 `GameConfig.advancedDismissalGold` / `normalDismissalGold` 配置。

## 招募名额与野外粮草

招募门槛为当前城池等级加一：一级 2 位、二级 3 位、三级 4 位、四级 5 位、五级 6 位。只统计本城存活驻军，外出的英雄不占招募名额。开局名单保留；进城、回城和转城允许任意数量的英雄，达到或超过门槛后禁止在本城抽取和签约，不删除已有英雄。抽取后如果有英雄回城导致满员，结果仍锁定，可等升级、出征释放名额后签约，也可放弃。

每位在外英雄独立累计粮草，行军、城下等待及交战每 10 秒扣本国 1 金币，扎营每 20 秒扣 1 金币；驻城不扣。按实际游戏时间结算，打开面板和观战照常计时。切换行军与扎营、改道、回城都不清除已累计的零头；月俸继续另外收取，主角虽免月俸，在外仍需粮草。

国库归零时，在外非交战部队立即扎营，禁止新出征和移动。正在拼杀的部队打完当前一场及结束动作，生还者扎营，不继续迎战下一位守将；如果这一胜已经满足占领条件，城池正常易主，生还进攻者满血留在新城外。断粮期间不累计新欠款。恢复资金后，玩家可重新下令，电脑在下一次决策恢复进攻；受袭的营地仍可正常进行野战防守。

`GameConfig.cityRecruitCapacityBase` / `cityRecruitCapacityPerLevel` 控制人数门槛；`fieldSupplySecondsPerGold` / `campSupplyRate` 控制粮草频率。电脑经营先按全国既有与拟派部队预留粮草、月俸和应急现金，再安排支出，详见下文预算规则。兵员库存容量依旧按城防与本城所属英雄数计算，与这里的招募人数门槛分别处理。

## 电脑国家预算

所有城市共用本国同一份现金预算。每次征兵、招募、升级、派遣或恢复一支部队之前，都根据最新余额与人员状态重算，避免多城重复花掉同一笔粮草。

- 默认预测至少未来九十秒；出征路程较长时，延长至预计攻城结束。行军时间沿实际路线逐段计算草地、山地和河流速度，城下排队及每位守将也预留交战时间。回城部队只计算抵达前的粮草。
- 收入仅使用当前拥有城市的欠收数值，不提前计算战利品或尚未占领城市的产出；逐个检查月结前与月结后的现金低点。月俸来自英雄 JSON，包含驻城、在外和拟招募英雄。
- 在上述支出之外留五金币应急。只有余款可用于征兵、抽取、签约和升级；征兵按当前驻军需求分批补充，不为填满上限而囤兵。
- 出征时仍优先选择强将，目标在可供养的敌城中加权随机：短途邻国优先，拥有城池更多的国家获得额外权重。每派一支就重新检查余下预算，不会一次把所有余将都派出去。
- 资金不足时，非交战部队优先返回行军时间最短的友城，返程也检查本国部队在此期间的消耗。暂时付不起返程的部队原地减半耗粮，恢复资金后逐队重新评估；已开始的拼杀和结束动画仍继续完成。玩家操作和各国实际收费规则不变。

参数位于 `GameConfig`：`countryAiEmergencyGold` 为额外应急现金（默认 5）；`countryAiSupplySafetySeconds` 为基础一个月之外的预测时间（默认 30 秒）；`countryAiBattleBudgetSeconds` 为每位守将预留的战斗时间（默认 30 秒）。这些数值仅影响 AI 规划，不修改实际行军或战斗速度。

## 邻国与扩张国家的进攻权重

出城与营地恢复进攻共用同一套目标选择。先进行补给预算检查，再按下式抽取目标：

`城池权重 = 领地倍率 / (1 + 实际行军秒数 / 30)²`

`领地倍率 = min(6, 1 + (目标国当前城池数 - 1) × 0.5)`

行军时间使用部队实际出发位置与当前地形速度，山川、河流会降低隔岸或隔山目标的吸引力。默认单城国家倍率为 1，三城国家为 2，五城国家为 3；同等距离下，大国的单座城市也更容易被选中。所有国家使用相同规则，包括玩家；城市易主后统计当前占领方，形成各国对扩张大国的共同压力。加权仍保留随机性，远处和较小国家也有机会成为目标。

`GameConfig.countryAiTargetTravelScale` 控制距离衰减尺度（默认 30 秒），`countryAiTargetDistancePower` 控制近邻偏好强度（默认 2）；`countryAiTerritoryWeightPerCity` 控制每增加一城的额外权重（默认 0.5），`countryAiTerritoryWeightCap` 控制最大领地倍率（默认 6）。调整这些参数只影响选敌倾向，已有补给预算仍优先执行。

## 城池接触位置

城池出入和途经拦截使用当前等级建筑的实体轮廓。`tool/extract_city_contacts.py` 从 `assets/images/terrain.png` 只读提取黑、灰、白的建筑像素，剔除草地和装饰旗杆，再加上英雄 16×16 方格需要的半径，生成 `lib/world/nes_city_contacts.dart`。更换城堡图块后运行此脚本更新轮廓；自定义建筑模板沿用其声明的矩形范围。城市点击区域仍覆盖整张图块，方便点选。

出城沿目的地方向贴住实体边缘；进城沿指令直线找到首次接触点，点击空白角时选择最近的有效墙体。升级或降级后同步在途目标和正在攻城的站位，等候部队依照原有顺序在轮到时重新靠近城池。

## 驻军顺序与英雄查看

`rom_heroes.json` 的 `heroes` 数组决定驻军顺序，主角固定排第一，其余依照文件排列。当前开头为主角、泽拉斯、亚彭龙、威拉斯、波塞伊，随后是其余高级和普通将领。编号只用于关联身份与资源，主角编号 40 不表示排在末尾；运行时不再维护另一份排序名单。

双方城池均展示“驻守英雄”，点击卡片查看同一套将领属性。只有我方城池提供出击操作；驻城名单仍排除已出征英雄。自动守城从列表末尾向前挑选当前可用将领，主角最后接战；增加驻军不打断正在进行的交战，下一场重新按逆序选择。我方主动出征仍由用户点选将领，其他国家的主动进攻沿用既有强将出征策略。

## 国家资金

```json
{
  "id": 0,
  "name": "阿尔马",
  "initialGold": 50
}
```

`initialGold` 是国家初始国库，多座城共用，不按城市数量重复赠送。NPC 每城留守人数改为该城 `initialLevel - 1`（最低零位），以开局 JSON 等级为准，之后升级、降级或易主都不改变这个基准。原 `garrisonHeroes` 字段已移除；玩家仍自由指挥。现有各国 40–80 金币的开局差异已迁移到 JSON。

## 进驻、攻占和战斗

- 活着的将领真正进驻本国城池或刚占领的新城时，恢复至自身生命上限。玩家与 NPC 都适用。贴近敌城开始攻城不会回血，守将留在原地交战也不会逐帧回复。
- 城内兵员只维护一份库存。确认出征时按库存最多调拨四兵，库存不足则有多少带多少；查看、选择和取消指令不扣兵。野外将领详情显示实际随军人数，驻城将领详情只显示战斗、内政、月俸。
- 每场守城开始前（包括换将和下一支敌军抵达），守将从本城库存重新领兵，最多四人。结束或进攻者撤离后，生还者归营、将领恢复生命；旧战斗快照保留当场伤亡。外出的进攻部队只使用携带的兵员，连续攻城和野战不从出发城远程补兵。
- 将领返回本国城池时，生还兵员加入库存并清空随军记录；重复处理不会重复入账。出征后可以继续征兵，回城时库存达到上限后多余生还者会被舍弃。降级、失去英雄或转城导致上限降低时，同样立即裁掉超额库存。
- 占领城池仍重置为一级，旧守军库存清空，不再生成十兵奖励。进攻部队的生还者正常归入新城库存；没有携兵就不会凭空得到士兵。升级只增加容量和产出，不增加库存。
- 攻城开打时记录初始城防等级。连续迎战的临时加成逐轮下降，例如三级城依次为 +12、+8、+4，地图上的真实等级和建筑外观在交战中保持不变。赢满初始等级对应的轮数，或清空全部可守城的英雄，即可占领；余下未出战英雄仍按失城规则清除。
- 若整场攻城结束仍未占领（进攻失败、撤离或部队消失），进攻方每赢一轮，独立判定一次 50% 城防损伤；每次命中降低一级，最低一级。零胜和同归于尽的轮次不增加次数，重复结算不会再次抽取。实际占领仍直接重置一级，不再额外掷骰。概率由 `GameConfig.cityDamageChancePerVictory` 配置，临时加成使用本场初始等级，最终损伤从城池当前真实等级扣除。
- NPC 使用同一套库存与出征扣兵规则。空闲驻军不提前分配士兵，AI 征兵仍实际扣款，领到足够兵员的部队才能按策略出征。
- 守城攻击加成为一级 +4、二级 +8、三级 +12、四级 +16、五级 +20。它作为普通拼杀的输入修正；原版基本碰撞运算继续沿用。原 ROM 解析出的等级修正为每级 +2，当前 +4 是本次指定的新平衡。
- 原有失城清除规则继续生效：出发城已失守的交战将领，即使打赢并进驻后回血，仍会在结算后消失，不会借恢复生命逃过清除。

全局的升级收入增量、储备容量、每将最多带兵人数及攻击加成仍在 `lib/game_config.dart`。JSON 是正式开局的数值来源；不附带 JSON 的简化测试地图使用默认产出、储备和原地图等级。JSON 的错误字段、负数、非法等级、重复编号和不存在的地图/城池会明确报错。初始兵员的容量校验延后至创建战役时执行，因为只有读取英雄归属后才能得到正确上限；运行中产生的超额库存会被舍弃。
