# 城池和国家开局配置

编辑 `assets/data/campaign_config.json`，保存后热重启 Flutter。JSON 在资源加载时读取一次；普通“重新开始”使用本次已加载的配置重新创建战役。无需修改 ROM 或包含地形图块的 `assets/maps/worlds.json`。

国家与城池文件包含 16 个国家和三张地图的全部 33 座城，英雄配置集中在 `rom_heroes.json`。`id` 用于关联，`name` 是便于查找的标签；国名和国旗来自地图目录，城池界面始终展示当前占领国名。地图编号 0、1、2 对应地图一、二、三。

## 每座城市

例如，地图一的奥尔梅：

```json
{
  "id": 1,
  "name": "奥尔梅",
  "baseIncome": 20,
  "initialReserveSoldiers": 10,
  "initialLevel": 2
}
```

| 字段 | 含义 |
|---|---|
| `baseIncome` | 一级城的基础月产出；每高一级额外 +5，再按收成和月俸结算 |
| `initialReserveSoldiers` | 本城开局贡献给全国库存的兵员，同国各城相加；出征或迎战时再从全国库存领取 |
| `initialLevel` | 初始城防等级，1–5，影响外观、月产出、储备容量和守城攻击加成 |
| `requiredGarrison` | 本城自动出征后最低留守将领数，非负整数，默认 2；0 允许全部出征，不随等级变化 |

目前阿尔马基础产出为 10，奥尔梅为 20，其余城池先设为 10。二级奥尔梅在本国时实际月产出是 25，被外国占领降至一级后为 10。外国城池先计算基础收入、等级增量和丰欠收，再乘 `GameConfig.foreignCityYieldFactor`（默认 0.5），逐城向下取整；如基础 21、丰收加 5，则实际获得 13 金币。界面、实际月结与 AI 欠收预算共用此规则。每座城的初始储备均填为 10；想设空兵营可改为 0。初始等级先沿用之前的地图等级，每张地图可以分别修改。

每国只有一份兵员储备，上限为 **本土城防等级总和 × 4 + 外国城防等级总和 × 2 + 全国存活英雄数 × 4**。一级、二级本土城加三名英雄共 24 个名额；如果二级城是外国城，则为 20 个。以开局的原属国家判断本土，反复易主及改名不改变原属国家；夺回本土恢复全额，易主仍重置一级。外国城每级贡献的容量也使用 `GameConfig.foreignCityYieldFactor`，英雄提供的容量不折半，防守攻击与招募名额规则保持原样。所有同国城池读取相同库存与上限，英雄无论驻城、行军或转往另一友城都只计一次。开局汇总各城 initialReserveSoldiers，再按全国实际容量校验；允许单城贡献超过它原先的局部容量，只要全国总量不超限。每位将领仍最多携带四兵，领兵从全国库存扣除，回城归还生还者，重复结算不增加兵员。

## 将领月俸与解雇

`assets/data/rom_heroes.json` 的 `heroes` 数组同时定义英雄顺序、属性与月俸：

```json
{"id": 0, "name": "泽拉斯", "salary": 3}
```

直接修改 `salary` 金币数即可。`id` 是英雄身份编号，`name` 用于查找；数组当前按展示顺序排列，调换数组位置会改变展示与迎战顺序，金额仍跟随对应英雄。主角 `id: 40` 固定为零且不占分档名额，从泽拉斯开始，第 1～5 位每月 3 金币，第 6～10 位 2 金币，第 11～15 位 1 金币，第 16 位起免费。这是新游戏平衡，原版报酬保存在同一条记录的 `romSalary` 中，仅用于对照。

开局驻军、招募预览、签约后月俸及全国月结都读取同一份配置。修改后热重启加载新开局；每位英雄必须填写 `salary`，负数、非整数、重复或不存在的编号会报错，主角不接受非零月俸。

我方城内与野外英雄面板下方的“取消”替换为红色“解雇”，同时显示返还金币；右上角关闭入口和取消选点仍可使用。高级将领返还 `10 + 内政` 金币，普通将领返还 `5 + 内政` 金币，返还进入所属国家国库。点击后立即离队并回到全国家共享招募池，停止后续月俸和野外粮草；重复点击或持有过期身份不能重复返款，重新签约后使用本局 JSON 月俸。

主角不可解雇，交战及结束动作期间暂不可解雇，敌国将领只有查看入口。城内解雇保留全国库存，英雄减少导致容量降低时仍按既有规则裁掉超额兵员；野外解雇的随军士兵一起离队，不远程归还。解雇不改变城防、归属和当月已签约次数，哪怕最后一位守将被解雇，城池也只会变为空城。返还基础金额由 `GameConfig.advancedDismissalGold` / `normalDismissalGold` 配置。

## 招募名额与野外粮草

招募门槛为当前城池等级加一：一级 2 位、二级 3 位、三级 4 位、四级 5 位、五级 6 位。只统计本城存活驻军，外出的英雄不占招募名额。开局名单保留；进城、回城和转城允许任意数量的英雄，达到或超过门槛后禁止在本城抽取和签约，不删除已有英雄。抽取后如果有英雄回城导致满员，结果仍锁定，可等升级、出征释放名额后签约，也可放弃。待签约结果含抽取当月在内保留 `GameConfig.heroOfferValidMonths` 个月，默认两个月；一月抽中可保留到二月底，三月开始自动归还全国家共享池、不退费。跨年使用累计月份，关闭面板不会续期；旧结果不能签约，已签约英雄不受期限影响。实际签约月份占用该城当月签约名额，到期归还不占新月份的抽取次数。

每位在外英雄独立累计粮草，行军、城下等待及交战每 10 秒扣本国 1 金币，扎营每 20 秒扣 1 金币；驻城不扣。按实际游戏时间结算，打开面板和观战照常计时。切换行军与扎营、改道、回城都不清除已累计的零头；月俸继续另外收取，主角虽免月俸，在外仍需粮草。

国库归零时，在外非交战部队立即扎营，禁止新出征和移动。正在拼杀的部队打完当前一场及结束动作，生还者扎营，不继续迎战下一位守将；如果这一胜已经满足占领条件，城池正常易主，生还进攻者满血留在新城外。断粮期间不累计新欠款。恢复资金后，玩家可重新下令，电脑在下一次决策恢复进攻；受袭的营地仍可正常进行野战防守。

`GameConfig.cityRecruitCapacityBase` / `cityRecruitCapacityPerLevel` 控制人数门槛；`fieldSupplySecondsPerGold` / `campSupplyRate` 控制粮草频率。电脑经营先按全国既有与拟派部队预留粮草、月俸和应急现金，再安排支出，详见下文预算规则。兵员库存容量按各城折算后的城防贡献与全国存活英雄数计算，与这里的招募人数门槛分别处理。

## 一次性武器

在 `assets/data/rom_weapons.json` 调整武器价格、直接伤害、反噬、解锁城数和初始国家库存；国家库存不限总量、同类合并，每将出征最多携带三件，使用后消耗，回城归还剩余武器。城池原面板内购买和选择，关闭面板清空选择，确认出征目标才带走。守城方禁用武器，野外双方可以使用，电脑采用同一套规则。十二种原版商店武器随城数解锁，三种事件武器可配置初始库存，其原版获取事件尚未移植。十五种原始数值、代码证据及适配范围见 [武器提取说明](nes_weapons.md)。

## 战斗撤退

出征和野战将领可尝试撤退，守城将领不能撤退；失败率 60%，双方先退回开场阵位，失败再播放阵亡动画，成功保留伤势与残兵并按原路回出发城。AI 高级将领只有生命严格低于最大值四分之一且胜算渺茫时才使用同样判定；返程仍扣粮草，并按整条来路预留资金。参数、动画与排队结算见 [战斗撤退](battle_retreat.md)。

## 电脑国家预算

所有城市共用本国同一份现金预算。每次征兵、招募、升级、派遣或恢复一支部队之前，都根据最新余额与人员状态重算，避免多城重复花掉同一笔粮草。

- 默认预测至少未来九十秒；出征路程较长时，延长至预计攻城结束。行军时间沿实际路线逐段计算草地、山地和河流速度，城下排队及每位守将也预留交战时间。回城部队只计算抵达前的粮草。
- 收入仅使用当前拥有城市的欠收数值，不提前计算战利品或尚未占领城市的产出；逐个检查月结前与月结后的现金低点。月俸来自英雄 JSON，包含驻城、在外和拟招募英雄。
- 在上述支出之外留五金币应急。只有余款可用于征兵、抽取、签约和升级；征兵按当前驻军需求分批补充，不为填满上限而囤兵。
- 出征优先选择足够攻下目标的强将编队，统一核算装备、兵员及含排队的整队粮草。弱城优先、强城筹备，来敌时转为守家；详见 [国家战略](country_strategy.md)。
- 资金不足时，非交战部队优先返回行军时间最短的友城，返程也检查本国部队在此期间的消耗。暂时付不起返程的部队原地减半耗粮，恢复资金后逐队重新评估；已开始的拼杀和结束动画仍继续完成。玩家操作和各国实际收费规则不变。

参数位于 `GameConfig`：`countryAiEmergencyGold` 为额外应急现金（默认 5）；`countryAiSupplySafetySeconds` 为基础一个月之外的预测时间（默认 30 秒）；`countryAiBattleBudgetSeconds` 为每位守将预留的战斗时间（默认 30 秒）。这些数值仅影响 AI 规划，不修改实际行军或战斗速度。

## 弱国优先与受袭仇恨

目标先按距离与守军粗筛，近处有弱城时优先在弱城中选择；核对可供养性后，用下式对候选加权。断粮营地恢复后先回友城整备，不直接重新盲攻：

`城池权重 = 国别权重 / (1 + 实际行军秒数 / 30)² / (1 + 守军难度 / 40)`

`国别权重 = (1 + 对目标国仇恨 × 0.02) / (1 + 目标国军力 / 80)²`

军力汇总国家城防、存活将领和全国兵员，默认优先进攻弱国，而不是按城池数优先围攻大国。行军时间使用实际出发点和地形速度，山川、河流仍影响成本。每支敌军实际抵达城下后，受袭国对来犯国仇恨加 20，同一支出征军对同国只记录一次；野战双方各加 20，上限 100，不自动衰减。玩家国家也记录仇恨并参与相同的国力比较，但玩家将领不自动出征。

`GameConfig.countryAiTargetTravelScale` / `countryAiTargetDistancePower` 控制近邻偏好；`countryAiStrengthScale` / `countryAiWeaknessPower` 控制弱国优先强度；`countryHatredPerAttack` / `countryHatredMaximum` / `countryHatredWeightPerPoint` 控制仇恨增量、上限和反击权重。已有留守、守家、胜算及补给预算检查仍优先执行。

## 城池当前名称

城池显示名由当前 ownerCountryId 对应的国名决定，每次易主立即更新，无需等原国灭亡。城池面板、行军提示、AI 行动和观战地点共用这一规则；原始地图标签保持不变，便于追溯配置和重新开局。

## 城池接触位置

城池出入和途经拦截使用当前等级建筑的实体轮廓。`tool/extract_city_contacts.py` 从 `assets/images/terrain.png` 只读提取黑、灰、白的建筑像素，剔除草地和装饰旗杆，再加上英雄 16×16 方格需要的半径，生成 `lib/world/nes_city_contacts.dart`。更换城堡图块后运行此脚本更新轮廓；自定义建筑模板沿用其声明的矩形范围。城市点击区域仍覆盖整张图块，方便点选。

出城沿目的地方向贴住实体边缘；进城沿指令直线找到首次接触点，点击空白角时选择最近的有效墙体。升级或降级后同步在途目标和正在攻城的站位，等候部队依照原有顺序在轮到时重新靠近城池。

## 驻军顺序与英雄查看

`rom_heroes.json` 的 `heroes` 数组决定驻军顺序，主角固定排第一，其余依照文件排列。当前开头为主角、泽拉斯、亚彭龙、威拉斯、波塞伊，随后是其余高级和普通将领。编号只用于关联身份与资源，主角编号 40 不表示排在末尾；运行时不再维护另一份排序名单。

双方城池均展示“驻守英雄”，点击卡片查看同一套将领属性。只有我方城池提供出击操作；驻城名单仍排除已出征英雄。自动守城从列表末尾向前挑选当前可用将领，主角最后接战；增加驻军不打断正在进行的交战，下一场重新按逆序选择。我方主动出征仍由用户点选将领，其他国家的主动进攻沿用既有强将出征策略。

## 国家资金

```json
{
  "id": 0,
  "name": "阿尔马",
  "initialGold": 50
}
```

`initialGold` 是国家初始国库，多座城共用，不按城市数量重复赠送。NPC 每城留守人数读取 `worlds[].cities[].requiredGarrison`，现有城市默认配置为两位，不再从城防等级推算，升级、降级或易主也不改变该城配置。国家级旧字段 `garrisonHeroes` 不使用；玩家仍自由指挥。现有各国 40–80 金币的开局差异已迁移到 JSON。

## 进驻、攻占和战斗

- 活着的将领真正进驻本国城池或刚占领的新城时，恢复至自身生命上限。玩家与 NPC 都适用。贴近敌城开始攻城不会回血，守将留在原地交战也不会逐帧回复。
- 每国兵员只维护一份库存，同国各城共用。确认出征时按库存最多调拨四兵，库存不足则有多少带多少；查看、选择和取消指令不扣兵。野外将领详情显示实际随军人数，驻城将领详情只显示战斗、内政、月俸。
- 每场守城开始前（包括换将和下一支敌军抵达），守将从全国库存重新领兵，最多四人。结束或进攻者撤离后，生还者归营、将领恢复生命；旧战斗快照保留当场伤亡。外出的进攻部队只使用携带的兵员，连续攻城和野战不从全国库存远程补兵。
- 将领返回任意本国城池时，生还兵员加入全国库存并清空随军记录；重复处理不会重复入账。出征后可以继续征兵，回城时库存达到上限后多余生还者会被舍弃。降级、失城或失去英雄导致全国上限降低时，同样立即裁掉超额库存。
- 占领城池仍重置为一级，但不会清空或转移双方全国库存，也不会生成十兵奖励。落败国家根据剩余城池、将领重新裁减超额，失去全部城池时库存清零；获胜部队生还者归入本国库存。占城和升级只增加容量与产出，不增加现有兵员。
- 攻城开打时记录初始城防等级。连续迎战的临时加成逐轮下降，例如三级城依次为 +6、+4、+2；城防每级只加两点攻击，不增加士气，地图上的真实等级和建筑外观在交战中保持不变。赢满初始等级对应的轮数，或清空全部可守城的英雄，即可占领；余下未出战英雄仍按失城规则清除。
- 若整场攻城结束仍未占领（进攻失败、撤离或部队消失），进攻方每赢一轮，独立判定一次 50% 城防损伤；每次命中降低一级，最低一级。零胜和同归于尽的轮次不增加次数，重复结算不会再次抽取。实际占领仍直接重置一级，不再额外掷骰。概率由 `GameConfig.cityDamageChancePerVictory` 配置，临时加成使用本场初始等级，最终损伤从城池当前真实等级扣除。
- NPC 使用同一套库存与出征扣兵规则。空闲驻军不提前分配士兵，AI 征兵仍实际扣款，领到足够兵员的部队才能按策略出征。
- 守城攻击加成为一级 +4、二级 +8、三级 +12、四级 +16、五级 +20。它作为普通拼杀的输入修正；原版基本碰撞运算继续沿用。原 ROM 解析出的等级修正为每级 +2，当前 +4 是本次指定的新平衡。
- 原有失城清除规则继续生效：出发城已失守的交战将领，即使打赢并进驻后回血，仍会在结算后消失，不会借恢复生命逃过清除。

全局的升级收入增量、储备容量、每将最多带兵人数及攻击加成仍在 `lib/game_config.dart`。JSON 是正式开局的数值来源；不附带 JSON 的简化测试地图使用默认产出、储备和原地图等级。JSON 的错误字段、负数、非法等级、重复编号和不存在的地图/城池会明确报错。初始兵员在创建战役时按国家汇总并校验容量，因为只有读取全国城防和英雄归属后才能得到正确上限；运行中产生的超额库存会被舍弃。
