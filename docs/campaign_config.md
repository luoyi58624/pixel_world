# 城池和国家开局配置

编辑 `assets/data/campaign_config.json`，保存后热重启 Flutter。JSON 在资源加载时读取一次；普通“重新开始”使用本次已加载的配置重新创建战役。无需修改 ROM 或包含地形图块的 `assets/maps/worlds.json`。

文件包含 16 个国家和三张地图的全部 33 座城。`id` 用于关联，`name` 是便于查找的标签；正式名称和国旗仍来自地图目录。地图编号 0、1、2 对应地图一、二、三。

## 每座城市

例如，地图一的奥尔梅：

```json
{
  "id": 1,
  "name": "奥尔梅",
  "baseIncome": 20,
  "initialReserveSoldiers": 10,
  "initialLevel": 2
}
```

| 字段 | 含义 |
|---|---|
| `baseIncome` | 一级城的基础月产出；每高一级额外 +5，再按收成和月俸结算 |
| `initialReserveSoldiers` | 开局的城池储备兵，不包含将领已经携带的四名小兵 |
| `initialLevel` | 初始城防等级，1–5，影响外观、月产出、储备容量和守城攻击加成 |

目前阿尔马基础产出为 10，奥尔梅为 20，其余城池先设为 10。二级奥尔梅的实际月产出因此是 25，城池易主降至一级后为 20。每座城的初始储备均填为 10；想设空兵营可改为 0。初始等级先沿用之前的地图等级，每张地图可以分别修改。

储备上限为 **城防等级 × 4 + 本城所属存活英雄数 × 4**。二级城、三名英雄提供 8 + 12 = 20 个名额；各城分别计算，国家总容量是所有城池之和。出征、扎营的英雄仍计入出发城，进驻另一城后名额转移，招募签约后新增名额，阵亡后移除名额；待签约结果不计入。初始化先按 ROM 记录去重英雄归属，再验证初始储备不超过实际容量。将领仍最多带四兵，扩容不会免费生成新兵。

## 国家资金

```json
{
  "id": 0,
  "name": "阿尔马",
  "initialGold": 50,
  "garrisonHeroes": 1
}
```

`initialGold` 是国家初始国库，多座城共用，不按城市数量重复赠送。`garrisonHeroes` 是 NPC 自动出征后每城至少留下的将领数量；玩家仍自由指挥。现有各国 40–80 金币的开局差异已迁移到 JSON。

## 进驻、攻占和战斗

- 活着的将领真正进驻本国城池或刚占领的新城时，恢复至自身生命上限。玩家与 NPC 都适用。贴近敌城开始攻城不会回血，守将留在原地交战也不会逐帧回复。
- 城池易主时先降为一级，储备直接重置为 10。不是在原储备上加 10，也不是把小兵直接塞给将领。友军重复进驻不刷新；连续结算同一次占领也不刷新。
- 降级、失去英雄或转城导致上限降低时，已有超额兵员保留，达到上限时不能再征兵。占城奖励也保留完整 10 兵，例如一级一将上限 8 时可暂时显示 10/8，消耗后再按新上限招募。
- 初始储备和占领奖励互相独立：把某城初始储备改成 0 或 25，不会改变占领后固定刷新 10 的规则。
- 守城攻击加成为一级 +4、二级 +8、三级 +12、四级 +16、五级 +20。它作为普通拼杀的输入修正；原版基本碰撞运算继续沿用。原 ROM 解析出的等级修正为每级 +2，当前 +4 是本次指定的新平衡。
- 原有失城清除规则继续生效：出发城已失守的交战将领，即使打赢并进驻后回血，仍会在结算后消失，不会借恢复生命逃过清除。

全局的升级收入增量、储备容量、占领奖励及攻击加成仍在 `lib/game_config.dart`。JSON 是正式开局的数值来源；不附带 JSON 的简化测试地图使用默认产出、储备和原地图等级。JSON 的错误字段、负数、非法等级、重复编号和不存在的地图/城池会明确报错。初始兵员的容量校验延后至创建战役时执行，因为只有读取英雄归属后才能得到正确上限；运行中出现的超额存量则保留。
