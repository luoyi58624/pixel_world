# 原武器动画还原

本次只读执行用户 ROM 的十五段切札动画，使用原精灵位置、姿势、绘制优先级和等待帧，替换原来的统一投射物效果。原 ROM SHA-256 见 [入口与帧数证据](nes_weapon_animation_evidence.json)。

## 原代码流程

`bank5 A901` 初始化演员及公共脚本，`A945` 根据效果编号跳转。固定区 `EF39` 更新十六个脚本演员，`E7F5` 生成 OAM 精灵，`FD4D` 推进动画帧及 PPU 传输。片段结束、恢复角色图块与姿势后，`A92F → E40C` 才结算武器伤害；死枪另对自身执行 255 点伤害。

原版使用前通过 `E690` 让两队以每帧一个原生像素返回各自阵位。Flutter 同样先归位、等待正在退场的单位结束，再播放武器时间线；播放完成后通过已有 NES 内核的 `E40C` 结算伤害。

## 图集与运行成本

- `weapon_effects.png` 共用图集为 1024 × 56，163 幅拼接精灵；士兵含红蓝两种，将领含主角、高级、普通三种职业的红蓝变体。
- `weapon_animations.bin` 共 119,210 字节，记录演员槽、姿势、坐标、绘制顺序；JSON 保存 96 个姿势及图集目录。启动时一次解码，运行时直接索引，不在游戏中解释这些 6502 动画指令。
- 使用 OAM 连续片段保持环形缓冲区首尾的覆盖顺序；按原姿势组选择变体，所以杖、炮中的角色变形不会被误改成固定职业。
- 原 0–9 演员槽关联双方实际生存单位；启动演出时锁定生存掩码，阵亡士兵不因动画脚本重现。10 及以后的额外效果按原脚本保留。
- 缓存当前物理缩放下的精灵图像，绘制时像素对齐；野外左侧释放按同一时间线镜像，继续使用当地地形背景。

## 验证与范围

`tool/verify_nes_weapon_animation.py` 重新运行原脚本，将原 OAM/PPU 精灵输出与导出文件重新拼接的 256 × 224 RGBA 画面逐帧比较。默认红蓝高级将领的十五种片段全部一致，完整计数和抽样哈希见 [逐帧验证](nes_weapon_animation_verification.json)。Flutter 另验证目录引用、实际观战绘制、武器消耗、碰撞概率、连续守将、野外两侧和不同帧长的一致性。

该比较针对提取的精灵动画层，未模拟真实 PPU 每扫描线八精灵的闪烁限制。沿用现有背景与 HUD；旧版武器名称文字窗口由现界面标题代替。音效、召唤及原武器获取事件不在此次移植范围内。

在项目目录安装 Pillow 与 py65 后执行：

```text
python tool/extract_nes_weapon_animation.py "ROM 文件路径"
python tool/verify_nes_weapon_animation.py "ROM 文件路径"
```

提取器校验原 ROM 哈希，保留已有武器价格与伤害配置，只补齐动画帧数。自动使用的开场及碰撞规则是当前游戏的新规则，并非原版的手动操作方式。
