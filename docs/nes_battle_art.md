# 战斗素材与固定队形

本次素材直接从已校验的《半熟英雄中文版》ROM 解码，原文件未修改。SHA-256 为 `c6dba3d22e2b27a804c9cb81d43d964a42bb6317e802224bfad07f37d5e3ee59`。

## 素材来源

以下文件偏移已包含 16 字节 iNES 头。战斗资源位于逻辑 bank 5，背景压缩图块位于逻辑 bank 2，绘制代码主要在固定 CPU 区域。

| 数据 | 文件偏移 / CPU 证据 | 用途 |
|---|---|---|
| 小兵与将领 8×8 位平面 | `0x01470A` 起 | 原始角色像素，不再使用临时手绘小兵 |
| 动作指针表 | `0x0160FA` / A0EA | 找到角色的图块拼接与属性表 |
| 拼接编号与属性 | EB77–EC38、E9B9–EB0D | 还原翻转、侧面两帧和碰撞姿态 |
| 武器追加部件 | `0x016415`、`0x016461`、`0x0164AD` | 合成原版拼杀武器，移除之前额外画出的白色剑线 |
| 阵营调色板索引 | `0x0146EA` / 8013–804F | 分别选取头部、衣服与皮肤颜色 |
| 背景压缩指针 | `0x00A68E` / EEC7 | 解出原版城内背景图块 |
| 名表模板、属性表 | `0x03EE82`、`0x03EEB2` / ED55–EE17 | 还原砖地、窗帘、城墙和前景栏杆 |

导出八套三帧战斗图集：小兵、高级将领、普通将领、主角，各有红、蓝配色。高级、普通、主角沿用项目已确认的三类外观，分别选用 ROM 角色模板 3、4、6；小兵为模板 0，另一阵营使用对应的 +7 模板。没有宣称将所有特殊人物模板都合并成了完全相同的原版角色。

每套图片为 96×32，横排三帧：侧面 A、侧面 B、拼杀。单帧采用 32×32 透明画布，在居中的原版 16×16 身体周围预留武器部件空间。人物本体仍按 16×16 的尺寸定位和点击。

背景直接解出编号 3、4、5：一级城为金色墙，二至四级为青色墙，五级为灰色墙。尺寸为原生 256×144，对应 NES 画面 Y=16 到 Y=159 的战场区域。

## 固定站位

CPU E758–E78E 使用一条整队横坐标，加各单位的固定偏移；士兵不会逐个追逐目标。

- 原始士兵 OAM Y：55、79、103、127；将领为 93。
- OAM 显示行比写入值晚一行；扣除上方 16 像素，再加 8 像素身体中心，得到士兵中心 Y：48、72、96、120；将领为 86。
- 初始前排中心 X：守军 48、进攻方 208；将领在前排后侧相隔 24 像素。
- 当前模拟按整支队伍同步横向接近与击退，随机减员后空位保留。伤害以整队兵力优先吸收，不再进行逐兵选取攻击目标。
- 存活单位没有纵向走动；阵亡后保留退场动画。

战斗计算已接入原 ROM 的普通拼杀片段，详见 [普通拼杀内核接入](nes_battle_rebuild.md)。小兵为共享兵力提供 20 HP 和 2 点碰撞强度；逐帧冲锋、反弹和随机减员由原始指令驱动，不再使用固定冷却或百分比位移。显示画布为 256×208，保留下面的双白框 HP 面板以及阵亡飞出空间。

普通人物武器计数要经过 **EA56 和 EA64 两次 LSR**，取 `(结束索引 − 起始索引) / 4`，不是只除以 2。实际执行 E9B9 验证，八个普通人物模板的近身姿势均为四块身体加一块武器；此前多取另一方向部件导致的双剑已修复，所有三帧图集按正确索引重新导出。

## 我方地图配色

`assets/images/hero/advanced_red.png` 与 `normal_red.png` 使用原地图六帧拼接数据，仅把蓝色主色 `#4240FF` 改成用户截图中的红褐色 `#B53120`。高级将领的浅色 `#E4E594`、普通将领的浅色衣服及透明边界保留。地图角色、城池面板、英雄信息和战斗界面均按英雄所属阵营选图。

ROM 提供颜色索引；RGB 使用本机 Mesen 的 NES 配色表，并与用户截图核对。战斗的皮肤色由原版战斗调色板选择，与大地图调色板分别保留。
