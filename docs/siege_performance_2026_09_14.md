# 密集围城卡顿修复与验证

## 复现与根因

只读提取本机最近存档的副本：7 年 2 月，21 支在外部队，20 支已纳入围城队列。其中队首和一名候战者卡在五级城右下凹角：队首选中的最近墙面被候战者挡住，候战者的补位路线又被队首挡住。

修复前，同一份存档推进约 30 游戏秒，两者位置不变，没有新城战。每个固定游戏步长仍重新展开围城格子、检查全部城墙，并为不能挪动的队员重复计算绕墙距离。

同时读取正在运行的 Windows Debug 游戏进程 CPU 采样，32715 个样本中，战役推进包含 19297 个，围城重排包含 14842 个，寻路包含 13417 个。围城重排约占战役推进样本的 77%；包含关系不能相加。

原始采样、存档副本、帧耗时和模拟日志均保存在忽略目录 `build/national_ai/`，没有修改用户的存档数据库。

## 修改

- 复用不可变建筑模板的围城格子；建筑外观改变时重新取得对应模板。
- 几何未改变时复用围城点的建筑占用检查结果；部队的位置、目标、排队顺序、占位、战斗或所有权发生变化时重新排位。
- 相同起点、终点与障碍布局不重复搜索已经失败的路线；障碍移开、死亡或目标改变后立即重试。缓存仅存在于内存，读档重新计算。
- 先排除不能实际让位的队员，再比较绕墙路程；碰撞检测直接计算两轴，减少内层循环的临时分配。
- 凹角队首的最近墙面被堵住时，按障碍格子的边缘寻找可到达墙面，保留实际到达顺序并经过正常行军和碰撞检查。

没有降低模拟频率、缩短碰撞检查范围、减少部队数量、改变圈距或跳过战斗规则。

## 同档性能对比

`tool/benchmark_campaign.dart` 使用游戏相同的 `GameClock` 固定步长和正式常驻 AI 后台；每六帧单独测量回放快照生成。两版都从同一份存档开始，测量约 30 游戏秒，包含首次运行开销。

下表是 Dart JIT 加 CPU 采样时的主线程战役推进耗时，单位毫秒：

| 倍速 | 修复前中位 | 修复后中位 | 修复前 P95 | 修复后 P95 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 1.603 | 0.186 | 2.357 | 0.941 |
| 16 | 29.923 | 3.487 | 43.442 | 21.093 |

中位耗时分别降低约 88.4% 和 88.3%。修复后开始实际交战，快照还包含新增战斗状态，不能把快照开销当成相同静止场景的对比。

将同一个基准工具编译为 AOT 可执行文件后：

| 倍速 | 战役推进中位 | P95 | 最大值 | 推进超过 16.67 ms 的帧 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 0.158 | 0.269 | 2.854 | 0 / 1800 |
| 16 | 2.498 | 5.065 | 7.532 | 0 / 113 |

以上测量不包含 Flutter 绘制、回放差量计算、存盘或后台等待，不能直接换算成游戏 FPS。快照生成独立测量：AOT 1 倍速 P95 为 1.308 ms，16 倍速为 2.004 ms；16 倍速首次快照仍有 19.571 ms 的初始化峰值。

复现命令：

```powershell
dart --observe=0 --no-pause-isolates-on-exit run tool/benchmark_campaign.dart build/national_ai/performance_user_checkpoint.json new_label 30 16
dart compile exe tool/benchmark_campaign.dart -o build/national_ai/benchmark_campaign.exe
```

工具拒绝覆盖已存在的结果目录。输出文件包括 `result.json`、`final.json`，启用 VM 采样时另有 `cpu.json`。

## 行为验证

99 项相关测试通过，覆盖围城、队列、城防换形、避让、撤退、存档恢复、军队恢复与调度审计。新增回归覆盖凹角队首换墙接战、静止堵塞后障碍移开、障碍死亡和更改目标；凹角测试逐帧检查人物不重叠。

实际存档使用正式后台续跑，在 335.48 游戏秒后攻下最后一城；共开始 24 场城战、17 次新出征，调度审计无异常。另以种子 9135 对三张地图各运行 600 游戏秒，每 180 秒读档，共 9 次恢复；三局分别占城 16、18、18 次，均无调度审计异常、重复将领、资源越界或不安全攻城样本。

Windows Release 构建成功。AI Worker 源码、版本与产物检查一致，指纹仍为 `4e2c7724`；本次未修改 AI 规划核心或共享规则。

尝试向已有 IDE 调试会话热重载时，Flutter 在处理临时 DevFS 时报告 Windows 文件访问被拒绝，未载入新代码。当前旧 Debug 进程仍运行；保存退出后从 `build/windows/x64/runner/Release/pixel_world.exe` 继续游戏即可使用修复。
