# 国家事件系统

点击城池打开所属国家面板，使用「国家情况 / 事件日志」标签切换。每个国家有独立日志、递增序号、监听和保留容量；同一国家的不同城池共用国家日志。城池易主后，面板显示新占领国的记录。查看日志不暂停游戏，开局之前的旧进度不会被伪造为历史记录。

## 默认只看最终决策

面板、累计条数、复制以及模拟默认输出，只包含 `decisionFinalized` 类型的 AI 最终决定。一次已采纳计划只生成一条，合并升级、招募、派将等实际执行结果，展开后可查看原因、目标、旧任务、新任务和国库前后值。玩家手动操作不计入 AI 决策条数；玩家国开启 AI 托管时，照常显示它的最终决策。

没有新行动的重复守城/积蓄决定不刷屏，只有方向或目标变化时新增；普通空闲判断不记录。未采用的候选计划、过期回复、排队、校验以及内部指令步骤不显示。实际执行了重复改派仍保留，避免掩盖真实调度冲突。已执行部分指令后失败，明确标记「部分完成」，不会误报整份计划成功。

## 内部追踪保留什么

以下内部事实用于按关联编号追查问题，不加入默认列表与统计：

- 操作事实：城防升级、士兵征募与调拨、英雄抽取/签约/放弃/解雇、出征/改道/扎营/进驻、武器购买与使用、操作失败。
- 经济：所有国家月结的收成、收入、月俸、国库前后值；逐部队实际粮草扣款与断粮。
- 战况：城下排队、交战与换守将、对阵结果、撤退申请和结果、占城/失城、英雄随失城清除。交战双方分别保留自己的战况事件。
- 决策：首次发现威胁、威胁变化、实际受袭后的仇恨账、开始判断局势、候选计划、校验结果、每条指令的实际结果、任务安排/改派/结束和守城兜底干预。
- 后台：排队、替换待处理请求、取消旧计算、丢弃过期回复、故障和重启状态。有国家身份的调度事件归该国，后台公共生命周期归全局记录。

威胁检测仅在状态变化时记一次；实际侵袭沿现有「同一出征军对同国只记一次」规则记录。即使仇恨已到上限，新的侵袭仍留下事件。不会逐帧记录坐标、每个小兵伤害或渲染活动。

## 字段与关联

`GameEvent` 保存 `runId / worldId / sequence / countrySequence / decisionSequence / tick / year / month`、事件类型、来源（玩家/AI/系统）、阶段（观察/计划/已执行/拒绝）、国家和目标国、英雄/城市身份、中文说明、原因及冻结的数据。`decisionSequence` 仅对本国最终 AI 决策连续编号，内部过程不占用此编号。

`decisionId` 包含后台会话、国家及请求编号，将本国的请求、计划、资源操作和将领任务串起来。战况由另一国的决策引起时使用 `causedByDecisionId` 表达因果，不冒充受袭国自己的决策。失败和被取消的建议不会标成执行成功；资源和任务的前后值按发生时保存，不随后续易主或将领离队而改写。

例子（格式示意，实际金额与原因来自执行时状态）：

```text
奥尔梅国：某将领将城防升至2级；征募4名士兵；命另一将领回援
原因：城池正遭到进攻，优先补足守城力量
金币：80 → 61；结果：已执行
```

## 内存、订阅和模拟文件

`lib/features/events/domain/game_events.dart` 是独立于 Flutter、AI 核心和文件系统的事件接口。`campaign.events.forCountry(id)` 返回本国日志；`listen` 返回解绑函数；`query` 可按类型、英雄、决策编号和全局序号过滤。

默认每国独立保留最近 1000 条最终决策和最近 1000 条内部追踪，追踪噪音不会挤掉最终决策历史。`finalDecisions` 读取最终决策，`decisionCount` 是最终决策累计数，`exportDecisionsJsonLines` 导出最终决策。面板展示最近 200 条，可展开结构化详情；「复制日志」导出该国当前保留的全部最终决策，首行含累计、保留和截断数量。面板仅在本国新增最终决策时刷新，不因内部流程频繁重建。正式游戏不默认逐条写磁盘，也没有日志轮询定时器。重开后建立新日志，旧的未导出内存记录不持久化。

模拟通过 `CampaignState.fromRom(eventLog: CampaignEvents(...))` 的 `onEvent` 接收器逐条写入缓冲文件，文件不受内存保留上限影响。接收器仅观察，不能改变真实决策和随机数；同步接收器失败会计入 `sinkErrors`，不会中断游戏。异步文件错误仍需由调用方在关闭文件时检查。

现有实际战役回归默认按国家写最终决策 JSONL，只为实际出现最终决策的国家生成文件：

```powershell
flutter test test/features/ai/country_ai_campaign_test.dart --dart-define=AI_CAMPAIGN_SECONDS=180 --dart-define=AI_CAMPAIGN_SEEDS=101,223 --dart-define=AI_CAMPAIGN_LABEL=event_audit
```

输出位于 `build/national_ai/`：

```text
event_audit.json                                      # 对局汇总与事件文件索引
event_audit_world0_seed101_country0.jsonl              # 玩家国（仅开启 AI 托管且产生决策时）
event_audit_world0_seed101_country1.jsonl              # 一个独立 AI 国
event_audit_world0_seed101_country2.jsonl              # 另一个独立 AI 国
```

该回归驱动显式使用同步 AI 以确定性推进实际游戏，不冒充完整异步压力测试。真实后台的排队事件由运行游戏及原生通信测试记录。

额外传入 `--dart-define=AI_EVENT_TRACE=true` 才导出完整内部追踪。`--dart-define=AI_EVENT_SNAPSHOTS=true` 会同时启用完整追踪、保存决策请求的完整公平观察，并在全局 `country-1.jsonl` 保存静态规则和地图。默认关闭，避免每次决定复制完整地图/快照。这些记录供离线核对，不送回 AI，也不等同于能重放全部随机战斗的存档。汇总的 `eventCount` 是实际写入文件的条数，`traceEventCount` 是内部事件数。

## 验证边界

事件测试覆盖国家隔离、独立保留上限、深度冻结、观察者错误隔离、实际费用、计划与执行关联、过期计划拒绝、受袭去重，以及开关记录后相同种子的行为一致；还验证多指令合并、部分失败、重复空闲决定去重和噪音不挤占最终历史。面板测试覆盖手机/桌面尺寸、切国不串日志、同国多城共享、实时刷新、过滤计数与复制范围。

事件系统本身负责观察；跨周期入城预留、调度顺序和召回优先级的后续修订见 [国家调度周期](ai_dispatch_cycles.md)。排查时可在完整追踪中检查 `taskReplaced / planRejected / commandRejected / guardIntervention` 及其关联 `decisionId`。
