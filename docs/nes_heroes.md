# 《半熟英雄中文版》英雄数据提取

本报告分析用户提供的 ROM，原文件未修改。SHA-256：`c6dba3d22e2b27a804c9cb81d43d964a42bb6317e802224bfad07f37d5e3ee59`。ROM 为 iNES，文件总长 262160 字节，PRG 256 KiB、CHR ROM 为 0，Mapper 4、水平镜像、带电池标志、无 Trainer。

## 结果

提取 41 位正式英雄：编号 0–39 为固定姓名英雄，编号 40 为玩家命名的主角。原始属性与报酬见 [CSV 表](nes_heroes.csv)，运行时属性见 [游戏 JSON](../assets/data/rom_heroes.json)。游戏JSON只包含实际配置字段，提取元数据不随游戏目录保存。[原始姓名字模图](nes_hero_names.png) 供核对汉化转写；姓名不是在 ROM 中搜索 Unicode 得到的。

类型已补充：0–9 为高级将领，10–39 为普通将领，40 为主角。编号 9 的显示名按用户校正为“希列洛”；原字模转写可用提取脚本和姓名字模图核对。分类及城名、国旗读取证据见 [补充核对报告](nes_cities_flags.md)。

## 可复核的读取证据

以下文件偏移包含 16 字节 iNES 头；PRG 偏移则不包含头。常规英雄表位于 16 KiB 逻辑 bank 6，MMC3 将 8 KiB bank 12、13 映射到 CPU 8000–BFFF。映射设置可见 CPU FEFC–FF13。

| 字段 | 首项文件偏移 | CPU 读取及解释 |
|---|---|---|
| HP 上限 | `0x01823C` | CPU 9301：`LDA $822C,X`；C1FB–C1FE 将初始值写入当前 HP 数组 `$7451+ID` |
| 战斗 | `0x0181BC` | CPU 930B：`LDA $81AC,X`，写入详情页变量 `$12` |
| 内政、报酬 | `0x0181EA` | CPU 9310–931E：同一字节高四位为内政，低四位为报酬 |
| 蛋相关标志 | `0x018213` | CPU CF77 读取 `$8203+ID` 并检查最高位；具体召唤结果还依赖运行状态 |
| 姓名偏移表 | `0x01829C` | CPU D0AC–D0D7：0–39 从 `$82B5 + offset[ID]` 读取字符串 |

姓名字符串的 `0x39`、`0x3A` 切换汉化字库页，后续字节索引 16×16 单色字模。CPU 9077、925E–927A 与 F2C4 的读取流程确认了字库页和 32 字节字模布局。Unicode 名字由这些字模转写；JSON 另存编码字节与源偏移，便于逐字复核。

主角编号 40 走 CPU D0D8 的特殊分支，从 RAM `$6FB0` 读取玩家输入，因此 JSON 的固定姓名为 null，游戏暂显示“主角”。初始化循环还处理编号 41–45 的特殊单位槽，但内政/报酬表只覆盖 0–40；没有把后面的相邻数据冒充特殊单位属性。

## 动态字段与提取边界

- 士兵：详情页 CPU 8CE9 读取 RAM `$702F+ID`。初始化 C1F0–C1F5 清零，初始地图上的行军单位在 C2F0–C2F2 设为 4；兵力交换代码检查上限 4。因此 JSON 分别记录驻城初始兵力 0 和上限 4，不把 4 当作 ROM 每位英雄的固定起始兵力。
- 王牌：属于动态库存槽，开局初始化为 FF，当前提取记录为空库存。它与召唤蛋不是同一字段；没有继续使用先前演示的“烈焰召唤”作为原版王牌名称。
- 召唤蛋：导出了能力标志、初始次数及状态字节；没有声称已经还原全部召唤表、成长或战斗算法。
- 城防、城池经济、升级成本及战斗伤害：以下新游戏规则独立配置，不宣称来自该 ROM。

## 当前 Flutter 规则

城池初始等级由玩法 JSON 配置，默认沿用原地图记录，最高五级。阿尔马初始一级；奥尔梅在三张地图中分别为二、三、四级。月收入为 `本城 baseIncome + (等级 - 1) × 5`，阿尔马基础产出 10、奥尔梅 20；升级由选中的本城驻守将领主持，基础费用依次为 30、80、150、300，再减其内政，最低零；出征、扎营或交战中的将领不能升级。各国初始资金由 `assets/data/campaign_config.json` 的国家配置独立设置（玩家 50，其余默认 40–80），每 60 秒推进一个月，各国独立抽取 50% 正常、25% 欠收、25% 丰收；后两者分别对每城减 10、加 5 金币，再扣该国英雄月俸，金币最低零。ROM 报酬保留在本报告与离线 CSV 中，游戏月俸只读取英雄 JSON 的 `salary`，当前经济规则见战役配置说明。

城池易主后统一回到一级，产出和升级费用随等级重算，外国占领者仅获得该城一半收入及城防兵员容量，按开局原属国家判断、夺回本土恢复全额；同一国家再次进驻不降级。建筑随 1–5 级切换原版模板，升级、守城降级和易主同步更新外观及接触范围。

国家兵员共用一份库存，容量为 `本土城防等级总和 × 4 + 外国城防等级总和 × 2 + 全国存活英雄数 × 4`，每名购买价 1 金币；英雄仍最多携带四兵，从储备补充时保留原有伤兵的血量。商店每城每月最多抽三次，放弃可继续抽，签约后当月停止，每次支付 5 金币，从未登场和已移除的非主角英雄中等概率抽取一位。英雄池对所有国家共享，玩家未签约的结果从池中暂时锁定，放弃或超出次月月底的签约期限后归还，关闭面板不会延长期限，已签约将领不会因此消失；NPC 先备足抽取及最高可能的签约费，再抽取并立即签约。普通将领免费签约，高级将领额外支付 10 金币；放弃返回池中且不退抽取费。签约英雄按原静态属性重新生成、满血且不附赠士兵，主角永不回收。配置集中在 `lib/core/config/game_config.dart`。非玩家国家按固定时钟自动经营，每城按开局等级减一保留将领，配兵后派战斗属性最高的多余将领随机攻打其他国家城池。国家初始资金、按开局等级确定的留守人数、招募门槛及野外粮草、决策节奏属于新规则，不能视作 ROM 中已提取的 AI 算法。

进攻方战败只损失出征英雄，不降低出发城等级、不改变产出、归属或留守英雄。连续攻城先逐轮降低临时守城加成；整场未攻下时，已赢轮次各以 50% 概率降低实际城防一级，最低一级。赢满初始城防等级对应的轮数或清空守将就占领，并移除未出战的败方英雄。其他城池英雄不连带移除；本城在外英雄在非交战时立即清除，正在交战则打完后无论胜败清除。主角阵亡或被移除、失去全部城池，任一情况均结束本局，即使还有其他英雄存活。结束后停止推进和指令，重新开始恢复本地图初始状态。英雄初始都驻在城内，地图只绘制真实在外部队。一级至五级城均允许多位驻军分别出征；城池面板只读取当前驻军，外出者仍保留原城归属和月俸，回城后重新入列。升级不会额外生成英雄。

普通拼杀已接入原 ROM 计算片段，当前城防平衡改为每级 +2 攻击、不增加士气，详见 [战斗内核说明](nes_battle_rebuild.md)。将领真正进驻本国或新占领的城池后恢复满血；驻城英雄开战前从全国共享库存领兵，结束后生还者归营；城池易主调整双方全国上限，库存不移交，只归还随军生还者，超额部分舍弃，不生成奖励兵。初始兵员、产出、等级与资金配置见 [开局配置说明](campaign_config.md)。

## 重新提取

运行 `python tool/extract_nes_heroes.py "ROM 路径"`。脚本校验指定版本哈希，并在结束时再次验证原文件内容未改变。输出 JSON、CSV 和原姓名字模图，不修改地图数据或原 ROM。
