# 《半熟英雄中文版》英雄数据提取

本报告分析用户提供的 ROM，原文件未修改。SHA-256：`c6dba3d22e2b27a804c9cb81d43d964a42bb6317e802224bfad07f37d5e3ee59`。ROM 为 iNES，文件总长 262160 字节，PRG 256 KiB、CHR ROM 为 0，Mapper 4、水平镜像、带电池标志、无 Trainer。

## 结果

类型已补充：0–9 为高级将领，10–39 为普通将领，40 为主角。编号 9 的显示名按用户校正为“希列洛”；原字模转写另存 `romGlyphTranscription`。分类及城名、国旗读取证据见 [补充核对报告](nes_cities_flags.md)。

## 可复核的读取证据

以下文件偏移包含 16 字节 iNES 头；PRG 偏移则不包含头。常规英雄表位于 16 KiB 逻辑 bank 6，MMC3 将 8 KiB bank 12、13 映射到 CPU 8000–BFFF。映射设置可见 CPU FEFC–FF13。

| 字段 | 首项文件偏移 | CPU 读取及解释 |
|---|---|---|
| HP 上限 | `0x01823C` | CPU 9301：`LDA $822C,X`；C1FB–C1FE 将初始值写入当前 HP 数组 `$7451+ID` |
| 战斗 | `0x0181BC` | CPU 930B：`LDA $81AC,X`，写入详情页变量 `$12` |
| 内政、报酬 | `0x0181EA` | CPU 9310–931E：同一字节高四位为内政，低四位为报酬 |
| 蛋相关标志 | `0x018213` | CPU CF77 读取 `$8203+ID` 并检查最高位；具体召唤结果还依赖运行状态 |
| 姓名偏移表 | `0x01829C` | CPU D0AC–D0D7：0–39 从 `$82B5 + offset[ID]` 读取字符串 |

姓名字符串的 `0x39`、`0x3A` 切换汉化字库页，后续字节索引 16×16 单色字模。CPU 9077、925E–927A 与 F2C4 的读取流程确认了字库页和 32 字节字模布局。Unicode 名字由这些字模转写；JSON 另存编码字节与源偏移，便于逐字复核。

主角编号 40 走 CPU D0D8 的特殊分支，从 RAM `$6FB0` 读取玩家输入，因此 JSON 的固定姓名为 null，游戏暂显示“主角”。初始化循环还处理编号 41–45 的特殊单位槽，但内政/报酬表只覆盖 0–40；没有把后面的相邻数据冒充特殊单位属性。

## 动态字段与提取边界

- 士兵：详情页 CPU 8CE9 读取 RAM `$702F+ID`。初始化 C1F0–C1F5 清零，初始地图上的行军单位在 C2F0–C2F2 设为 4；兵力交换代码检查上限 4。因此 JSON 分别记录驻城初始兵力 0 和上限 4，不把 4 当作 ROM 每位英雄的固定起始兵力。
- 王牌：属于动态库存槽，开局初始化为 FF，当前提取记录为空库存。它与召唤蛋不是同一字段；没有继续使用先前演示的“烈焰召唤”作为原版王牌名称。
- 召唤蛋：导出了能力标志、初始次数及状态字节；没有声称已经还原全部召唤表、成长或战斗算法。
- 城防、城池经济、升级成本及战斗伤害：以下新游戏规则独立配置，不宣称来自该 ROM。

## 当前 Flutter 规则

城池初始等级读取原 ROM 各城初始化记录，最高五级。阿尔马初始一级；奥尔梅在三张地图中分别为二、三、四级。新月收入为 `10 + (等级 - 1) × 5`；升级费用默认为当前等级乘 200。每国初始金币 50，每 60 秒推进一个月，各国独立抽取 50% 正常、25% 欠收、25% 丰收；后两者分别对每城减 10、加 5 金币，再扣该国英雄月俸，金币最低零。ROM 的报酬字段保留原值，当前游戏月俸按原值除 5 向上取整；主角无论原值如何都固定为零。

城池易主后统一回到一级，产出和升级费用随等级重算；同一国家再次进驻不降级。建筑随 1–5 级切换原版模板，升级、守城降级和易主同步更新外观及接触范围。

城池储备兵员容量为 `10 + (等级 - 1) × 5`，每名购买价 1 金币；英雄仍最多携带四兵，从储备补充时保留原有伤兵的血量。商店每次支付 5 金币，从未登场和已移除的非主角英雄中等概率抽取一位。普通将领免费签约，高级将领额外支付 10 金币；放弃返回池中且不退抽取费。签约英雄按原静态属性重新生成、满血且不附赠士兵，主角永不回收。配置集中在 `lib/game_config.dart`。

进攻方战败只损失出征英雄，不降低出发城等级、不改变产出、归属或留守英雄。守将战败才让实际被攻打城池降一级；该城原已一级则易主，并移除未出战的败方英雄。其他城池和在外英雄不连带移除。主角阵亡或被移除、失去全部城池，任一情况均结束本局，即使还有其他英雄存活。结束后停止推进和指令，重新开始恢复本地图初始状态。一级城只允许同时派出一位英雄，更高等级可派出其他可用驻军；升级不会额外生成英雄。

当前按整队碰撞结算：小兵各 20 HP、攻击 1，部队伤害为存活兵数加将领“战斗”属性，再乘累计士气差加成。伤害先扣兵力并随机减员，溢出才扣英雄。每 500ms 消耗 5%–10% 剩余士气，初始士气仍取最大 HP 加兵数；全场按 50 点折算，各自按受伤点数后退，到终点收势、举剑后重新冲锋；墙边按伤害差超过实际退路的部分追加本轮承伤。原版普通拼杀已做只读逆向与 6502 执行验证，也采用共享兵力，但数值公式不同，详见 [战斗算法报告](nes_battle.md)。无守将的城池可直接占领；胜利英雄进驻新城并保留伤势。当前未实现召唤或存档。
