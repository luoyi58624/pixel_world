# 国家 AI 验收记录

日期：2026-09-10。计划及实现说明分别见 `.claude/plan/national_ai_strategy.md`、`docs/country_strategy.md`。

## 验证范围

本次使用当前工作区的三张实际地图及资源配置，保留用户原有的 `assets/maps/worlds.json` 改动。旧 AI 对照从 `e28aa56` 导出到忽略的独立目录，用相同地图、英雄、武器、经济配置运行，未切换工作分支或改动上层仓库。

规则回归使用真实战役接口和实际战斗执行器；同步 AI 驱动只在测试中显式注入。测试数据不会进入运行时策略，也没有用试打结果生成胜率表。三地图保留种子为 101、223、337，各运行五分钟；最初调试使用的 7、19、43 没有作为最终保留样本。

定向覆盖：战前有效升级、战中开场名额、挡位清理、主持者价值、零金币合法筹款、升级/解雇后的容量、守军自动补兵、全国唯一库存、月结前后现金低点、远征全路线供养、选择性回援、援军到达名额、截击与自伤成本、途中失城、实际进驻、空城迁移、战斗/返程锁定和真实战后清除。另验证无隐藏终点读取、评估不修改世界、工作配额和完整动作组上限。

通信覆盖：原生常驻 Isolate；十国共用单一执行槽；持续同国更新保留排队资历；过期和重复结果；切换会话；构建不匹配；超时/崩溃最多两次重启；取消与有界队列。真实 Chrome 中运行 Dedicated Worker，与原生同一请求比较 24 份结果，验证取消，并在请求期间持续执行页面动画。

## 实测结果

Windows Release 与标准 Web Release 构建通过，Worker 源码、指纹及产物一致。定向回归 **275 项通过**，静态检查无问题；下列三项既存界面测试单独记录，没有算入通过数。测试文件限定为 AI、关联规则与界面子集，没有执行全量测试。

真实浏览器使用本机 Chrome、1024×768 逻辑视口、1.75 倍像素比，在子路径 `/strategy/` 加载，完成拖拽后继续观察十五秒。以下均为毫秒，最大值包含冷启动：

| 构建 | 主环境 P95 | 主环境 P99 | 主环境最大值 | 后台规划最大值 | 接受回复数 | 最高排队数 |
|---|---:|---:|---:|---:|---:|---:|
| Debug JavaScript | 0.201 | 2.1 | 11.799 | 13.0 | 84 | 8 |
| Profile JavaScript | 0.201 | 1.699 | 9.101 | 15.0 | 84 | 7 |
| Release WebAssembly | 0.1 | 1.3 | 9.0 | 21.0 | 66 | 9 |

三个页面均只有一个实际 Dedicated Worker，无运行时异常、重启或过期丢弃；WebAssembly 请求记录包含 `main.dart.wasm`，不是仅验证 JS 回退。单份观察约 18～22 KB，后台执行期间地图拖拽和页面动画继续。独立 Worker 对照还完成了 24 次与原生同输入结果比较及取消验证。

这些是有界样本，不是“所有帧均低于 1 毫秒”的承诺。后台计算虽已移走，快照、编码、回调和命令仍有真实开销。不同前端的随机开局与时序也不完全相同，不用回复数量比较策略胜负。

| 指标 | 旧 AI | 新 AI |
|---|---:|---:|
| 城池易主次数 | 43 | 31 |
| 不同出征将领合计 | 138 | 161 |
| 交战中危险溢员采样 | 1648 | 0 |
| 高级将领未交战即移除（含解雇） | 3 | 2 |
| 断粮停营的部队秒数 | 0 | 0 |

新 AI 的高级将领“随城且未交战而被清除”单独计数为 0；表中两次未交战移除包含合法解雇，不能等同于战斗阵亡。真实运行观察到远征、回援、截击、撤离、整备以及重新出兵；没有重复英雄和越界储备。过期/依赖失效的命令由执行器拒绝并重新请求，而不是强行执行。

这组样本显示名额安全明显改善，粮草稳定性保持；短期扩张更保守。它是旧 AI 自对弈与新 AI 自对弈的系统行为对照，不是直接新旧一对一胜率测试，也没有证明长期统一率提高。同步回归的总耗时包含后台规划逻辑，不能当作正式主线程开销。

[可复核数值记录](national_ai_measurements.json) 保存了逐局结果、后台版本和浏览器指标；大体积截图、逐帧日志保留在本地 `build/national_ai/`。SDK 为 Flutter 3.47.1 / Dart 3.13.1。



## 已知范围与限制

- 这是静态风险驱动的国家策略，不是 ROM 原版国家 AI，也不是精确战斗预言。后续武器、随机伤害、途中来敌、对手升级都可能改变实际结果。
- 无法保证所有地图必然统一。更谨慎的防守可能降低短期城池易主次数；需要把国家存续、保将和长期扩张一起评估，不能只看攻城总数。
- 据点迁移目前只把能及时进驻的空城视作可靠逃生方案。有守军的目标仍可作为普通扩张候选，但不会在原城即将失守时把预计获胜当作已经获救。
- 路线只比较有限绕点，可能放弃实际存在但超出候选范围的复杂路径。预算耗尽时返回保守或部分建议，不宣称找到了全局最优解。
- 无头 Chrome 的页面帧间隔受本机刷新率和调度影响；这里测量的 AI 准备、消息回调和命令提交开销不能替代移动端整机帧率。冷启动含地图编码和后台加载，峰值高于稳定帧。主环境直接接敌的最后一道规则保护没有独立计入常规协调器分位数。
- 本次 Debug 网页为 `flutter build web --debug` 产物，不等同于 Chrome DDC 热重载调试器；原生常驻 Isolate 在 Flutter 测试中实际执行，Windows 发布另行构建。
