# 普通拼杀的原版内核接入

验收参照是用户录像 `QQ20260909-083642.mp4`，原 ROM SHA-256 为 `c6dba3d22e2b27a804c9cb81d43d964a42bb6317e802224bfad07f37d5e3ee59`。ROM 和用户录像均未修改。

## 这次实际替换的内容

普通拼杀不再使用此前的百分比士气、固定冲锋速度、伤害换算平移距离或定时冷却。提取 992 字节原始计算片段，在每场独立内存中执行，再将位置、生命和兵位同步到 Flutter。它只执行普通拼杀的指令，不启动整台 NES，不包含 PPU 或音频仿真。

| 行为 | 原始位置 | 当前接入 |
|---|---|---|
| 右军移动和 A 键积累 | E4C4–E55B | 8.8 定点速度、逐帧加速、反弹刹停、靠近举剑 |
| 左军自动操作与移动 | E55C–E648 | 原版随机源、周期表和资源消耗 |
| 碰撞 | E3B8–E40B、E649–E68F | 双方按强度查表反弹；取消固定停顿、冷却和镜头抖动 |
| 伤害与减员 | E411–E4B9 | 先扣共享兵力，再扣英雄；原版随机槽位减员 |
| 撞墙 | E54B、E5E4 | 双倍对方基础强度再调用伤害例程，停速回冲 |
| 阵亡运动 | DC21–DCA4 | 横向弹回、重力和三次边界反弹，之后移除精灵 |
| 站位和步态 | E758–E7E9 | 四名士兵固定纵坐标；步态随原生横坐标切换，近身举剑 |
| 红条 | E1C6–E1D7 | 由战斗属性和修正初始化，通常为 min(63, 4×(战斗+修正+1)−1)，不读取最大 HP |
| 胜方走场与结果 | E6B2、E6C9、DE3E | 等阵亡动画结束，每帧走一像素至对侧，举剑并显示原结果窗口，等收尾结束再结算 |

主循环按 DCE5 的先后执行右军、左军、阵亡运动和精灵位置。保留算术进位、字节溢出及 D102 随机源，避免把汇编中的连续 ADC 或移位误写成普通公式。

城防一至五级攻击加成按指定数组设置为 +1、+3、+5、+8、+12。武器属性和价格保持原值。城池初始等级、储备、产出和国家资金由独立玩法 JSON 配置，见 [开局配置说明](campaign_config.md)。离线对照方式见 [战斗平衡验收](combat_balance.md)。

城防只以完整攻击加成的 25% 参与击退强度差，比例由 `GameConfig.cityDefenseRecoilScale` 调整，再应用双方共用的击退差倍率；伤害仍使用完整城防攻击，红条士气和冲锋加速度不增加城防。五级城的 +12 在击退差中按 +3 参与，最终速度仍按内核整数查表计算。野战没有城防份额，不受此比例影响。

当前每名存活士兵提供 20 HP 和 1 点碰撞强度，不是每轮独立扣 1 HP。战斗 15、4 兵且无城防修正时强度为 19；武器、普通碰撞和撞墙造成减员时立即扣除对应强度，士兵全灭只保留将领和城防基础值，士气独立。恢复旧战斗存档也会按实际存活人数重新计算。原 ROM 开场每兵 +2 且锁定强度的行为仅在显式启用 `originalSoldierRules` 的原版逐帧对照测试中保留。

## 显示和交互

- 背景、角色三个动作、固定兵位沿用原 ROM 数据；新增从 ROM 提取的 40 位英雄姓名字模。
- 战场扩展为 256×208 的显示画布，地板仍是 256×144；下方使用黑底双白边框、姓名、HP 和红条。阵亡角色可以飞过下方信息框，不在地板边缘提前淡出。
- 移除额外影子、头顶小血条、伤害数字、受伤变色、旋转淡出和撞墙碎屑。HP 留在下方面板，红条表示独立资源。
- 拼杀、阵亡和胜方过场共用后台时间；返回地图、重新观战不重开或治疗。整场交战结束自动返回地图，连续守将之间仍停留在战场。主角死亡的结束面板等本场退场动画播完后显示，正常战役指令在最终结算后继续被禁止。
- 双方冲向敌人时每12帧独立尝试随机蓄力，成功率为剩余士气的一半加25个百分点；成功扣一点士气，随机累积1到4点。后退和停留时不蓄力。碰撞时按原分档的6倍换算冲击强度，上限24，碰撞后清空积累；高士气提高机会但不保证成功。
- 原版内核每场按实际参战兵数重建共享兵力，当前小兵生命是这份整队兵力的投影。兵员来源由战役统一管理：驻城将领开战前从库存领最多四兵，结束后归还生还者；外出将领继续使用实际携带的兵员，回城再归营，超额部分舍弃。守城结束或真正进驻本国、新占领城池时将领恢复满血；连续进攻未占领的城池和野战不远程补兵。每场固定自己的槽位引用，归营和再次领兵不会改写旧战斗记录。

## 复核与可重复证据

士气初始化由 E1C6–E1D7 原指令计算，当前英雄属性范围内对应 `min(63, 4×(有效战斗属性+1)−1)`，不读取当前 HP、最大 HP 或士兵数量。原电脑逻辑在 E55C 调用 D102 随机源推进 17 相位，经 E5F5 和 E629 表转换后累加 18 计时器；溢出时 AF 减一，在原代码检查的反弹阶段将 19 增一。碰撞 E3FE 将积累换为 `积累为0时无加成，否则 min(4, (积累>>2)+1)` 点碰撞强度，随后清空积累。它不是按血量初始化的百分比士气系统。

上述自动蓄力段仅保留用于原 ROM 对照；正式游戏使用独立 `morale` 配置（0到100）初始化士气，并使用冲锋中的随机蓄力。城防按等级数组增加碰撞攻击，不增加士气或冲锋加速度。原字节未改写；这是新游戏规则，不是对原 ROM 数值的宣称。

`tool/extract_nes_auto_charge.py` 只读执行同一原指令段，生成 `test/fixtures/nes_auto_charge_frames.json`；`test/features/battle/nes_auto_charge_test.dart` 比较 1,400 帧的士气、积累、随机源、位移、伤亡和碰撞状态。原手动/无输入的 4,000 帧对照仍保留，用于验证基础指令没有因自动控制适配而改变。原音频、特殊召唤和完整 NES 输入仍不在本次移植范围内。

运行 `tool/extract_nes_battle_kernel.py` 可以再次从指定 ROM 只读提取指令并生成 py65 对照数据。`test/features/battle/nes_battle_kernel_test.dart` 比较四组、共 4,000 帧的完整计算快照，包含位置小数、带符号速度、随机源、红条、生命、减员槽、弹地位置和次数。

```powershell
python tool/extract_nes_battle_kernel.py "ROM 路径" --py65-path build/nes_analysis/deps
flutter test test/features/battle/nes_battle_kernel_test.dart
```

对照数据执行原始计算，只跳过 CF49 的战役登记和 E8F3 的 OAM 写入；CF49 会清除将领战役身份，当前由 Campaign 接管，其普通死亡入口已是零 HP、零兵力。它们不替代碰撞、随机数或运动算术。逐帧比较证明的是这些给定初始状态和输入下的计算一致性，并非整台 NES 的逐周期仿真。

本次生成的 `build/nes_battle_rebuild/nes_vs_flutter.mp4` 左侧是原录像、右侧是 Flutter。按首次接触对齐，两段使用同组主角与开伦，右侧不代按 A。原录像包含未记录的 RAM 随机种子、先前操作与按键时序，因此没有声称每个减员槽、每次伤害或战斗结束帧与录像完全相同。

本机 Flutter test 的 JIT 测量：20 场同时运行，五组样本每组模拟 10 秒，纯战斗计算每个世界逻辑帧的中位耗时约 0.111 ms。该值不包括画面绘制、地图逻辑或平台启动，不代表所有设备的帧率。

## 已知边界

此次接入的是录像中的**普通将领与小兵拼杀**。召唤蛋、王牌、特殊生物、原版音效/音乐没有一并移植；野战地形减攻与新背景仍是当前游戏的扩展。HUD 的数字和边框由 Flutter 重绘，主角自定义名及新增中文提示采用系统字形。不能将这些未接入部分称为完整原版还原。

## 后续反馈修正

- 原先胜军走到对面就立即结算，导致最后的举剑和结果窗口没有机会显示。现在增加独立结果停留阶段：败方退场 → 胜方走场 → 停住举剑、显示原字模 → 自动返回；双方阵亡跳过走场，显示原版“互刺··”。
- 原版在 DD77/DDED 先启动结束曲，再走场；DE4F 等曲子完成，DE53 再等 9 帧。用 py65 从战斗曲 8C 切入原音频驱动测得胜利曲 92 为 194 帧、失败曲 93 为 223 帧；走场时间包含其中，不能在走完后再等完整曲长。当前复用这个 60 Hz 时序，仍未播放原音乐。
- 原窗口 22 位于 NES `(80,32,96,32)`，裁掉战场顶部 16 像素后为 `(80,16,96,32)`；胜利、失败和互刺字模从 bank 5 的 A62D/A639/A642 提取，不依赖系统字体。提取与计时可通过 `tool/extract_nes_battle_ending.py ROM路径 --py65-path build/nes_analysis/deps` 复核，地址和原字节见 `docs/nes_battle_ending.json`。
- 结果按玩家所在一侧显示；玩家守城或作为野战左军获胜时同样显示“胜利”。NPC 之间观战默认右军视角。这是对当前战略游戏双方均可观战的适配。结算、治疗、回收、换守将及自动离场都等结束停留完成，后台战役时钟继续运行。

- 双剑来自提取器只对武器表长度除以 2。原版普通模板在 EA56 和 EA64 实际执行两次 LSR，只追加一块武器。八套图集已重新只读提取，数据测试固定检查四身体加一武器。
- 出发城失守时，行军和扎营英雄立即清除；处于城战或野战的英雄打完后无论输赢均清除。标记独立保存，不会因进驻新城、夺回老城或主动撤离而被绕过。
- 回收仍使用同一个全局池，战斗未结束前不释放英雄身份。游戏结束只停止世界经营和行军，已经交战的失城部队继续结算并清除。
