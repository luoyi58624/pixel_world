# 攻城队列与随机守将

本规则是新游戏的战役调度，普通拼杀仍使用现有 NES 战斗内核。

## 守将抽选

每支进攻部队实际开始攻城时，从目标城存活、仍驻城且未参加其他战斗的将领中等概率选一位。出征、阵亡及其他城市的英雄不在候选池。连续攻城击败一位守将后，按降级后的城防重新抽选剩余可用驻军。

抽选只发生在开战或下一位守将上场时。等待、查看面板、观战和普通时间推进不会重抽当前守将。随机源独立于收成、招募和国家经营；`CampaignState.fromRom(defenderRandom: ...)` 可注入随机源以复现测试。

## 排队与野战

- 每座城同时只接待一支进攻部队，连续守将和换人间隙都保留名额。同一国家的不同城市各自处理攻城。
- 其他部队到达城下便停止，按实际抵达先后接战；同一固定时间步内同时抵达时按英雄编号稳定排序，不以派兵顺序插队。
- 等待期间仍参加野外遭遇检测。不同国家将领相遇便在城外决战，同国不交战；当前城战和野战参与者不会被第二场战斗抢走。
- 队首正在野战时，后续队伍可以先进入攻城。胜者保留伤势、原目标与原抵达顺序，败者移除。主动改道或扎营会退出队列，再来需要重新排队。
- 城堡升级或降级时，等待者保持原位。轮到后再步行到新接触点，队首这段调整期间后面的部队继续等待。
- 目标变为友城后按正常进驻处理；无存活驻军且没有正在进行的攻城时，可以占领。换守将间隙剩余驻军全部离城也会结束攻城并结算占领，不会卡住。

## 验证

`test/siege_queue_test.dart` 覆盖随机守将、候选过滤、不重复抽选、到达顺序、换人占位、多城并行、等待遭遇、胜者恢复队列、败者清除、主动退出、空城结算及城堡尺寸变化。
