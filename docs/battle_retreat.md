# 战斗撤退

仅出征的进攻将领和野战双方可撤退，守城将领暂不开放。观战底部与地图人物面板提供同一个撤退入口，直接显示“60% 失败即阵亡”。返回地图只关闭观战；交战中的移动、扎营不能再绕过判定免费脱战。列阵和普通拼杀时可操作，胜败已经确定、阵亡及换将过场中不可改变结果。

每次有效指令只掷骰一次：60% 失败，40% 成功。重复点击、无权操作或已经结束的战斗不消耗随机数。无论成功或失败，双方先从当前位置连续退回开场阵位，期间停止新的拼杀和士气消耗，已阵亡单位继续完成退场。回到起点后，失败方才归零生命并播放原版整队阵亡、弹地及胜方结束动作；成功则保留伤势和残兵，在起点短暂停留后自动退出观战。回收池、主角阵亡及失城规则均等结束动作完成后结算，进攻失败不降低出发城等级。

成功后默认按本次离城以来实际经过的拐点反向返回出发城，不瞬移、不沿直线抄近路，也不改成最近友城。抵达原城后恢复将领生命并归还存活兵员，超出全国容量的兵员按既有规则舍弃。撤退过场结束后允许手动移动，合法改令取消自动返程，保留当前位置、伤势与兵员；电脑经营仍不自动改派返程部队。途中仍消耗粮草，断粮时保留返程路段并扎营，恢复资金后自动继续返回。出发城失守仍按原有规则清除部队。

撤退成功后，同一对手在分开到接触距离之外前不立即重开野战；其他敌军仍可拦截返程部队。返程途中再次获胜或成功撤退后继续剩余原路。野战未撤退的一方继续交战前的行军或扎营指令。攻城方撤退结束整场攻城，归还守军生还兵员并恢复守将生命，释放排队位置；此前已胜轮数仍在结束时独立判定城防损伤。

电脑仅高级将领会主动考虑撤退，普通将领和守城将领不会。至少观察两次碰撞后，用双方当前总生命与最近碰撞伤害估计还能承受多少轮；只有将领当前生命严格低于初始最大生命的四分之一，且自身可承受轮数低于敌方的 60% 时，才尝试一次同样风险的撤退。仍有安全武器时先使用武器；仅兵数落后不会触发撤退。每次新碰撞评估一次，不逐帧反复掷骰。国家预算计算返程的每个路段及地形耗时，避免把返程粮草花在新征兵和升级上。

参数位于 `lib/core/config/game_config.dart`：

| 参数 | 默认 | 含义 |
|---|---:|---|
| `retreatFailureChance` | 0.6 | 失败概率 |
| `retreatExitSeconds` | 1.2 | 双方退回开场阵位的时间 |
| `retreatResultSeconds` | 0.6 | 结果停留时间 |
| `aiRetreatMinimumClashes` | 2 | 电脑最少观察碰撞数 |
| `aiRetreatSurvivalRatio` | 0.6 | 双方预计可承受轮数的劣势阈值 |
| `aiRetreatHealthRatio` | 0.25 | 当前生命必须严格低于最大生命的此比例 |

撤退概率、决策和返程属于新增玩法；普通拼杀及失败的阵亡演出继续使用已接入的 NES 内核。撤退随机源独立于战斗、收成、招募和城防损伤，不改写 ROM 或素材。
