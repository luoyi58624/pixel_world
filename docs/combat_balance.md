# 战斗平衡验收

## 目标与条件

长期调参目标为同条件野战胜率约50%；无武器进攻一级城约30%、二级城低于5%、三级及以上不出现进攻胜例。基准双方战斗力15、生命95、基础士气50、四名满血士兵。当前优先验证独立的士气时钟和纯属性对照，下方旧版概率不能代表新算法的胜率。所有武器属性和价格保持原值，包括炮的25金币、80伤害，不增加减伤或强制胜负规则。

纠正了击退取整偏差：先对带符号的强度差取整，再加回基准值。普通伤害使用原中值曲线取消中间取整后的比例，并累计小数余量，随机差异来自士气。关闭士气或将随机幅度设为0时，同属性双方逐帧等血并自然同归于尽，不通过额外抽签或写死胜负来匹配胜率。

## 士气速率验收

开场总士气为将领士气与城防士气之和，不截断总值。红条最多显示100点，超出的部分在初始化时就加入第一轮积累，红条从开战起照常消耗。首次碰撞的 `C = 超出100的部分 + 第一轮正常消耗形成的积累`，当次结算后清零；第二轮起只使用正常消耗形成的积累。开场不足100不补满，关闭士气时超额也不参与。

一次正常拼杀中，士气攻击加成为 `B = C == 0 ? 0 : min(4, floor(C / 4) + 1) * 6`，对应0、6、12、18、24五档；士气积累完整进入既有公式，攻击加成仍沿用24点上限。剩余士气本身不直接乘到伤害上。

设 `P = min(63, 将领攻击 + 城防攻击加成) + 存活小兵数 + B`，当前普通伤害为 `D = 1 + 3P/8`，保留原中值曲线的基础项与比例，取消中间按四点攻击分档及末尾逐次舍弃小数。伤害以八分之一点为单位累计，支付整数部分，小数按受击方跨碰撞保留并写入存档；先扣整队兵力，再扣将领生命。每增加一点攻击，每八次相同强度拼杀累计多造成三点伤害。15、16、17攻击连续八次分别造成53、56、59伤害。

士气增加的精确普通伤害为 `3B/8`，也参与击退差值；撞墙使用现有对方基础强度与倍率进行追加结算。武器继续使用原始整数直伤，不参与普通伤害换算，也不消费小数余量。原ROM逐帧对照路径保持原始指令计算。`test/features/battle/damage_precision_test.dart` 使用固定参数验证整个0～63攻击范围、存档小数恢复、80点武器直伤，以及零随机满士气一级城守方获胜的回归样本。

`test/features/battle/morale_controls_test.dart` 显式注入固定参数，不导入 `GameConfig`：每秒8、12、16点时，100点分别在750、500、375帧耗尽；7.5点每秒连续4秒剩余93、85、78、70点，证明小数跨秒保留。随机12±4覆盖256个种子、512个单方样本，逐秒检查8～16点，100点耗尽时刻必须在375～750帧；测试另覆盖开关、零随机对称、跨秒存档恢复与旧存档兼容。

按60帧/秒，100点士气的理论耗尽范围为6.25～12.5秒。战斗提前结束或撤退后不继续消耗，游戏暂停也不推进逻辑时钟。测试只固定算法输入与预期行为，调整正式游戏配置不改变这些测试样本。
