# 国家 AI 调度周期

本次修订针对频繁改令、无必要召回和跨周期入城名额丢失。规则以游戏时间计时，暂停期间不推进。

## 顺序与频率

- 开局立即安排资源，结果真实落地后使用新观察执行防守，再执行进攻。
- 资源整理每 30 秒到期：按全国需求补兵、必要城防、招募与目标配装，共同预留已有部队粮草、月俸和流动资金。
- 防守哨兵每 8 秒到期；资源整理完成后也扫描一次。攻击阶段在防守之后，复核当前防线才使用余力扩张。
- 一个国家同一时间只允许一份未完成请求，后台排队按等待时间处理。威胁和战斗变化不再每半秒重启全套规划。
- 过期或未采用的请求至少等 2 秒重试；阶段交接不补跑过去漏掉的周期。实际触发时间会加上有界排队和计算耗时。

`AiTuning.resourceIntervalSeconds` 默认 30，`intervalSeconds` 默认 8，`resourceCashBuffer` 默认 12。入口仍为 `GameConfig.nationalAi`。既有的安全名额检查、断粮扎营、战斗锁定继续由真实游戏命令保证。

## 防守优先级

1. 比较真实迎战顺序、剩余城防攻击加成、守将当前生命、可调拨士兵和可见来敌的属性。AI 名单与游戏一致，按内政、攻击力降序排列后从队尾迎战。静态占优则保持现有远征。
2. 有缺口时，优先使用本地资源：补兵、有效升级和合法招募。驻城将领不再主动出城截击，也不派弱将出城消耗敌军；已经在野外的部队仍可就近截击。紧急防守可以在资源常规周期之间执行必要补强，依然受全国后勤预算约束。

局势接近或评估未知时不撤走守城核心。超员先转移弱将，为强将保留实际迎战名额；判断是否弃城时也检查被挡住名额的现有守将。只有明确来袭、现有核心也明显落后且没有能保住城池的本地或回援方案时，才考虑安全撤离。撤离只表示保全将领，仍将原城标为防守风险未解决，不再因此压过真正能守住城的方案。
3. 本地可执行方案不足时才考虑打断远征。行军按地形和绕行路线积分，必须在来敌最早接触窗口前到达，并留出反应时间；赶不及的援军不会被记作可用防守力量。
4. 已安排且能及时到达的援军计入未来防线，名额跨周期保留。已有援军足够时不再召回第二人。被标记清除、交战锁定或返程锁定的部队不能被普通命令“救活”。

守将已经阵亡但结束动画尚未播完时，AI 会预先扣除这一个确定失去的迎战名额；观察与执行校验一致，避免在动画期间错误招募或承诺新援军。实际城防和战斗结算规则不变。

未发生的战斗不试打、不逐轮扣血，不把静态余量当作胜率。没有可行救援时保留无解说明，不虚构额外交战拖延时间。

## 采购与进攻一致

目标排序共用 `targetPriority`，考虑距离、守备、仇恨、领土规模和城池收益。采购与进攻共用 `assessRaid`，按真实守军顺序扣分配的兵员储备，并使用同一城防和装备门槛判断单军/编队需求。

资源阶段用只读账本报价整队兵员与月俸，资金不足时保留筹备目标；虚拟报价资金绝不提交给真实世界。进攻阶段使用已准备的随军兵员，不再设置装备门槛。新招募英雄的身份和属性必须实际揭晓后，下一阶段才能调动。

## 日志与验证

最终决策包含 `stage`（resources / defense / attack）、实际行动、理由、资源变化和持续任务。回援理由保留城防、静态余量、预计路程秒数和危险窗口。普通无行动的阶段不会重置日志去重状态。

定向用例见 `test/features/ai/country_ai_schedule_test.dart`，覆盖周期、同国单请求、失败重试、暂停、强防线不召回、本地补强优先、跨周期名额、已有援军足够以及资源/进攻交接。其他 AI 用例使用逐逻辑帧驱动，避免把一次大跨度时间推进误当成完整三阶段调度。

### 本次验收

- 104 项定向回归通过，静态检查通过；测试范围为国家 AI、关联经济/战斗规则、事件和暂停，没有执行全仓测试。
- 三张实际地图 × 种子 101 / 223，每局推进 180 秒：合计 13 次城池易主、57 位出征将领（各局内去重再相加）；危险溢员采样 0，断粮停营采样 0。
- 共导出 331 条最终决策，每国单独文件；归属、连续决策编号和汇总数量核对一致。模拟文件与截断现场保留在 `build/national_ai/cadence_audit*.json*`。
- 真正的 Chrome Dedicated Worker 轮换执行完整周期、资源、防守和进攻四种请求，24 次结果与纯 Dart 核心一致，取消校验通过。构建指纹为 `28093e66`。
- Windows Release 和 Web Release 构建通过；实际浏览器完成地图加载及国家日志页操作，无运行时异常。

这组有限样本没有证明 AI 必然统一或永不失城：其中两位高级将领仍按真实失城规则在出战前被清除。模拟只用于验收，不把结果或未来战果交回运行中的 AI。后台对照用于功能一致性，不将浏览器启动时的帧间隔当作整机性能结论。
