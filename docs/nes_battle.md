# 普通拼杀：ROM 证据与当前游戏规则

分析文件为用户提供的《半熟英雄中文版》，SHA-256 `c6dba3d22e2b27a804c9cb81d43d964a42bb6317e802224bfad07f37d5e3ee59`。原 ROM 未修改，没有操作或暂停用户的模拟器。

## 最重要的区别

原版普通拼杀采用**双方整队碰撞，共享兵力值先吸收伤害**。画面有四名小兵，却不是四次独立攻击，也没有“将领再随机砍一名小兵”的额外普通伤害。兵力不足时随机移除一个仍存活的士兵图形，剩余伤害才扣将领 HP。

这与当前项目按用户要求设计的逐兵对位、最近目标、将领随机攻击、士气差百分比增伤属于两套算法。不能把项目里的参数直接称为原版数值。

## 已由原始 6502 指令验证

CPU 地址为固定区 C000–FFFF；本文件中这些地址对应文件偏移 `CPU + 0x30010`，包含 iNES 头。英雄表由逻辑 bank 6 映射在 8000–BFFF。

| 机制 | 可观察代码 | 结论 |
|---|---|---|
| 初始兵力 | E4BA–E4C3，调用 D33E 乘法 | `$702F+英雄ID` 的士兵人数乘 20，存为双方 `$12/$13` 共享兵力；4 兵为 80 |
| 基础碰撞强度 | E1D8–E1EA | `B = 战斗属性 + 场地/城池等修正 + 2×士兵数`；城池等级修正的读取见 E0C1–E0D4 |
| 输入积累的增益 | E3FE–E40B | 积累为 0 时加 0，否则 `min(4, floor(积累/4)+1)`；E3B8–E3D6 将它加在基础碰撞强度上 |
| 一次碰撞伤害 | E411–E426，D0F1–D101 | 设对方有效碰撞强度为 `P`，`q=floor((P+2)/4)`；受到 `q+1+(随机字节 mod (q+1))` 点整队伤害 |
| 伤害吸收与溢出 | E428–E451 | 优先扣共享兵力；不足部分扣 `$7451+英雄ID` 的将领 HP，不会同时对每名小兵各扣一份 |
| 减员阈值 | E454–E47D；E4B5 表 | 0/1/2/3/4 兵对应最低共享兵力 0/1/21/41/61，相当于 `ceil(剩余兵力/20)` |
| 谁阵亡 | E462–E471 | 随机取四个槽之一，若该槽已退场则重抽；调用 E496 改变其动画状态。这里没有按对位距离挑伤害对象 |
| 碰撞反弹 | E649–E68F | 双方强度之差查表得到有符号 8.8 速度，两边均反弹；弱势方反弹量更大，并非只让一方平移 |
| 墙边追加伤害 | E54B–E552、E5E4–E5EB | 位置触及边界后，以对方**基础强度的两倍**再调用伤害例程；不是固定“受伤 +50%” |

有一个容易误读的细节：E411 先把 `q` 放入零页 `$00`，但 D0F1 随后会把 `$00` 改成 `q+1`。因此最低伤害是 `q+1`，不是仅看局部指令得到的 `q`。本次通过执行原例程检查了这个副作用。

例子：没有场地修正和输入增益时，战斗 15、4 名士兵得到 `P=23`，一次普通碰撞对对方**整队**造成 **7–13** 点伤害；战斗 5、4 名士兵得到 `P=13`，对应 **4–7** 点。原始随机源再取模，不能严格称每个结果等概率。

若兵力剩 5 点而本次受到 7 点伤害，兵力归零，将领只损失溢出的 2 HP。若兵力从 80 降到 60，兵数从 4 变 3，被移除的士兵槽由随机数选择。

普通开战初始化会重新按当前兵数乘 20 建立兵力池，没有为每名小兵读取单独的受伤 HP。将领的当前 HP 则有独立持久数组。

## 红条不等于将领 HP

数字 HP 由 E973 从 `$7451+ID` 读取；红条由 E992 从另一个变量 `$AE/$AF` 读取。E1C6–E1D5 在常规属性范围内将这个条形资源初始化为：

```text
min(63, 4×(战斗属性 + 修正 + 1) - 1)
```

因此无修正时，战斗 15 的将领红条为 63；战斗 5 的为 23。HP 95 和 HP 99 不是这个条形资源的直接输入。

E4C4–E4E2 读取手柄 `$42` 的最高位，消耗玩家红条资源，并在反弹阶段积累增益；D582–D5A0 为手柄串行读取，标准手柄先读 A，经过八次左移后落在最高位，按键顺序参见 [NESdev 标准手柄文档](https://www.nesdev.org/wiki/NES_controller)。AI 的 E55C–E585 使用随机数和周期表驱动资源消耗。原版这里不是每轮随机消耗 0%–25% 后按消耗差增伤。

本报告称它为“红条资源”，没有仅凭变量用途断言其官方中文名称就是士气。

## 验证方式和范围

`tool/analyze_nes_battle.py` 把 bank 6 与固定区放入隔离的 6502 内存，直接执行 ROM 子程序，只替换 D102 的随机字节来源。D0F1 的取模、进位和零页副作用均保留。验证包含：

- 41 个碰撞强度 × 256 个随机字节，检查实际伤害范围。
- 原始英雄属性初始化、4 兵对应 80 兵力。
- 4 个不同随机值触发不同士兵槽减员。
- 兵力不足时的真实 HP 溢出。
- 相同和不同强度的反弹速度，例如 23 对 13 为 -550，13 对 23 为 -750（8.8 定点数）。

机器可读结果及代码字节见 [nes_battle_evidence.json](nes_battle_evidence.json)。这不是整台 NES 仿真，也未完成王牌、蛋、召唤生物、所有场地修正、输入节奏和逐帧动画的完整逆向，不能据此声称全战斗系统已经一比一还原。

复核命令：

```powershell
python -m pip install --target build/nes_analysis/deps py65
python tool/analyze_nes_battle.py "ROM 路径" --py65-path build/nes_analysis/deps
```

## 当前项目保留的自定义规则

- 每个小兵独立 25 HP，基础攻击按用户最新意见从 5 降到 **1**；先对位，目标阵亡后找最近的存活敌兵。
- 将领基础攻击仍为其“战斗”属性，每次选择敌方随机小兵；敌兵全灭后改打将领，将领 HP 归零才判败。
- 每场将领交战的初始士气为将领最大 HP 加存活小兵数；当前伤势不降低初始士气。换守将时重新初始化士气，但保留实际将领和小兵伤势。
- 每轮双方随机取整数比例 0%–25%，消耗当前剩余士气乘比例后向下取整的点数；点数差只加给较高一方，作为本轮伤害增加的百分点。剩余不足 4 点时可能一直投入 0，但攻击不会停止。
- 士气投入较低的一方逐帧后退 32 个原生像素，平手不退；真实靠墙的**受击单位**受到的伤害再乘 1.5，其他单位不连带受罚。先结算接触时的伤害，再执行本轮后退。
- 小数伤害保留用于计算，界面最多显示两位小数。每秒最多一次整轮拼杀，接近时不消耗士气或造成隔空伤害。

仅将小兵攻击降到 1，不会改变高战斗将领可能两击击败 25 HP 小兵的事实。若希望更接近原版的部队存续时间，下一步应选择共享兵力池，或另行调整将领的独立输出方式；本次没有擅自改掉用户已确认的将领伤害规则。
